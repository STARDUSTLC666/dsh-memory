# 第五轮独立留出版本说明

原始实验、开发集和验证集的记录全部保留。检查发现，四个非私有事实家族在旧开发、验证和留出拆分中复用了相同的题目、初始代码和验收输入，只更换了项目命名空间。它们应视为模板重复，不能用于声称新任务泛化。

在任何留出模型运行开始前，新建 `independent-holdout-v2`：12 个新的任务接口及验收案例，沿用六个任务家族和原有留出 A 阶段的 12 次历史会话。其行为规格的哈希互不重复，也不与旧三个拆分重复。每个初始实现均未通过，12 个参考实现全部通过，并核对了人工推导的样例真值。各组预算、基础模型、评分器、检索排序、条件判断和反思关闭状态保持一致。

新增任务分别覆盖批量路由、路由计数、到期时间表、保留置顶记录、区间占用时长、最早可预约空档、多个配置继承、配置回滚、按用户筛选本地最新事件、日历窗口、配置补全和计划启用配置。完整规格和真值见该目录的 `task-protocol-v2.json` 与 `fixtures-v2`。

Oracle 仍只读取 A 阶段证据图和来源索引，由 B 的公开命名空间选择来源；不读取 B 隐藏真值或参考实现。60 项交付检查已通过，其中 12 项无关上下文与虚拟 D 的工具 JSON 长度在固定官方 tokenizer 下完全相同。相同长度不代表全会话 API 计费相同。

验证集结束后，按事先登记的规则确定唯一候选，再复制不可覆盖的选择记录及哈希。留出只用于确认或否定该候选，不据其结果调整规则，也不从留出结果重新挑选其他候选。

该版本是在发现拆分缺陷后、完成开发阶段之后构建的补充独立验证，不冒充从项目开始就封存的测试集。它检验已见六个家族中的新任务接口，不能证明对未见家族、真实仓库问题或公开大型 Benchmark 的泛化。
