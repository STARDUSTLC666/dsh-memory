# 并行异常、权限与回归

## 进程回收断言

第六轮 T3b 统计整机所有 python.exe，允许 +1。并行测试或 venv 启动会扰动全局读数，且历史记录缺少完整 PID，不能把原故障直接宣判为代码竞态。受控历史测试中自身验证器已回收，额外测试噪声仍触发 T3b，复现了该断言的非局部性。

修复测试隔离：追踪自己启动的 3 个 Popen，要求全部回收、零允许残留。Windows venv 还会启动真实解释器，新增可信测试注入的 PID 握手，在超时之前用 OpenProcess 打开真实执行进程的稳定句柄，等待退出，避免只验证启动器和 PID 复用。产品 verifier.py、沙箱、0.8 秒超时与阻断断言未放宽。失败快照先记录再清理；仅终止本测试拥有的确切句柄。

实际 worker 泄漏负对照：3 个启动器均已回收，但保留一个真实执行进程时 T3b 必须失败，日志中 executor exited=False；测试清理该确切进程。另保留全局噪声、直接子进程泄漏等诊断。最新版 15 个断言和定点变异自证通过。Windows venv 行为可参照 [CPython 3.12.10 launcher 源码](https://raw.githubusercontent.com/python/cpython/v3.12.10/PC/launcher.c)，结论同时有实际进程句柄观测支持。

## 身份和权限分层

签名凭据验证及租户请求绑定在原生 MCP 启动层；clearance/actor/private_visibility 由 Secure 层执行；条件适用性与模型拒答另计。公开主集中的任务误拒不能解释为认证误拒。

合法签名且具 read+info 的测试身份可 whoami/recall/get；原生预算溢出得到空包 INCOMPLETE。低 clearance/无 actor 无法取私有节点；无效签名、未知/撤销/过期身份以及外租户签名配显式 default 租户请求被拒。初次 read-only 缺 info 的测试凭据拒绝符合协议，后续授予测试身份合法 read+info；未改授权实现。跨租户首次探针未注册独立 tenant root，不能证明隔离；最终使用注册 tenant 物理根及明确 MDCG_TENANT 绑定，旧误设探针日志保留。

普通诊断只含授权 ID/哈希/跨度/预算，不复制记忆正文和凭据；正文仅在隔离实验原始记录。测试数据不代表生产隐私数据全量 DLP 保证。部署时必须保持显式租户绑定，不能把未注册共享目录当作隔离保证。
