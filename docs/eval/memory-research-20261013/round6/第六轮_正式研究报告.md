# 第六轮：证据保真交付、泛化验证与 Token 成本

本轮是阶段性实验与探索，未更新生产 DSH 插件、正式 Memory、远程 PR 或 Issue。完成 **556 次预注册主对照 + 11 次入口试跑 + 10 次新版本合法owner补测 + 96 次修正版Oracle诊断 = 673 次实际 DeepSeek Harness 会话**。模型调用全部保存原始日志，没有 API/桥接基础设施中断。主对照中 11 次来自两道已标注的身份规格错误题，原分数保留，不将它们解释为算法失败。

**结论：D 的保真收益在新任务中复现，但 D 本身还不是完整保真实现。G 显示小幅成本下降和更明确的超预算处理，样本不足以证明正确性无退化，也没有实现更短的单次交付；本轮保留 D 为研究基线，G 默认关闭，不进入预测式 Memory-RSI 或生产集成。**

## 1. 历史结果与源码根因

复查第五轮 252 次有效运行及真实检查反馈，报告数字一致。旧留出集 B18/24、D24/24，D 未缓存 Token +16.26%。历史 ZIP 和所有被引用原结果哈希保持不变。

损失链为：**完整 trace 写入图 → lexical/RRF 排序 → recall 对正文做前缀摘录 → 实验桥把已摘录内容装入 JSON → 再截整个 JSON → Agent 只拿到 ID/轨迹前缀，来源关键事实缺失**。D 在相同候选 ID/顺序上重新 get 来源正文，因此能恢复已有证据。外层 JSON 截断是旧实验桥行为，不能概括为全部原生插件行为；原生 MCP 仍可 get，本比较没有给 Agent 追加 get 工具。

D 的遗漏包括：compact schema 不交付独立 non_applicable_conditions / verification_basis，桥接时用 trace.context 覆盖原生 condition_space，query_excerpt 窗口仍可切断限定条件，元数据占满预算时条目会被跳过，完整性状态没有传给 Agent。观测 time_window 不等于知识有效期。

本轮冻结第五轮 Python 源码和 B/D 变换，外加所有组共用的既有 MdCGSecure 可见性闸。192 次桥接预检、16 次归档桥输出逐字对拍，以及使用真实旧工作树资源的 88 次普通授权 B/D 对拍均通过。新一轮 94 组 B/D、48 组 B/D/G 的候选顺序、selected ID、有效查询均一致。详见《第六轮_P0源码与基线审查.md》。

## 3. 最小 G：整包保留与显式退让

只修改上下文交付组件，没有修改写入、排序、检索、反思 Prompt、权限或评分。新函数 default enabled=False，关闭时与 D 的开发样本输出 12/12 逐字一致。

G 保留选中来源正文原文、全部原生适用/不适用条件、观测时间窗与显式生效期/版本、来源稳定 ID、receipt、验证状态及条件 comment。相同元数据只放一次，省去D固定列的可选null占位；只合并同一 ID 且源码/元数据一致的重复出现。来源正文不做语义压缩，不删矛盾来源。

预算覆盖整份工具 JSON，使用固定官方 V4.1 tokenizer；API usage 仍是计费 Token 真值，不能把离线 tokenizer 当作服务端全部角色模板的精确计数。开发阶段只比较 512/750/1024 三档的完整包覆盖，11 道有效开发题在 750 档全部完整，于任何 G 模型实验前固定 750。整包放不下时返回 INCOMPLETE/DEFER，不交付部分事实。COMPLETE_SOURCE_BUNDLE 只表示已选来源完整，不表示检索已穷尽、事实已验证或可以直接执行。

## 5. Token 与延迟：不能只看总数

P1 D 对 B 未缓存输入+输出 **-4.51%**，交付响应 Token **-14.70%**，模型请求少 11 次；此方向与去掉 trace/双重 JSON 交付开销一致。

G 留出对 D：未缓存输入+输出 **-3.68%**，总 Token **-6.27%**，但单次交付合计 **21,778 对 19,768（+10.17%）**；未缓存输入 **65,688 对 64,473（+1.88%）**，输出 **15,938 对 20,270（-21.37%）**，模型请求少 4 次，cacheRead **39,680 对 44,672**。因此这次总成本下降主要伴随更少调用/更短输出，**不能称为交付文本压缩成功，也不是纯缓存收益**。

G 未缓存成本变化的家族聚类描述区间约 **-8.11% 至 +0.52%**，并未证明稳定节省。P50/P95 为含 DSH 启动、工具与 API 的端到端延迟，受同机并行任务和 API 波动影响，非服务器推理基准。实际货币账单无法取得，未估造金额。

## 6. 保留与丢弃的证据

G 留出核心原句完整覆盖 42/46，D40/46。G 有 **4/48 次**整包超预算，均明确 INCOMPLETE 并不发部分事实；其中两次正确拒答、两次造成需要事实的任务失败。仅在成功交付的包中，原文/条件没有截断；不能把“已交付100%完整”偷换成“全部请求100%召回”。

G 独立负条件字段完整交付 8/12，另外 4 次随整包退让不交付；正常交付的负条件为 8/8。D 为 0/12 个字段逐字保留，但部分来源正文也有否定语义，因此该字段指标不能解释为 D 所有负条件语义都丢失。

被省去的是 trace 诊断日志、空 metadata 槽及完全相同的 metadata 副本。没有证明可安全删掉来源正文里的长背景：缺少可信证据片段边界时，G 保守退让。未来若研究片段选择，应单独引入可验证的来源 span 标注，不同时改排序和反思。

## 7. 关键失败证据

- 旧 B 的多跳来源已在候选/pack 中，来源事实在嵌套 trace 前缀中丢失；D 恢复后成功。这支持交付瓶颈，不支持更换 RRF。
- P1 长历史题有 B 成功、D 失败：B 的早期经验 note 含正确事实，D 舍去 note 后对长来源做关键词窗口，关键事实再次丢失。不能把第五轮24/24推广成所有来源长度均保真。
- G 的独立负条件完整交付修正了一个普通批次标签的误拒，但另一次仍误拒，说明格式不能消除所有 Agent 判断错误。
- G 另一个配对胜利只是输出格式：D 已拿到3/3原句，却省掉了标签的 `tag-` 前缀，G保留前缀。不能把这次胜利算成检索或证据恢复收益。
- G 留出 revision-2 两次输出了 revision=2 的标签，当前要求 revision=1。两份来源和条件都在完整包中，外部真值能定位其采用了不适用版本。rep2 的模型 reason 甚至写出了正确 revision=1 标签，submit_answer.answer 却填另一个标签；**最终参数与解释不一致**。保真并不替代执行结果的独立验收。

模型自述只作附录，根因以 A 来源、可见 pack/交付、最终提交和独立评分为依据。不能仅凭 reason 认定模型内部纠正过。

## 9. 交付、回滚与下一阶段

代码仅新增 md_cg/evidence_budget.py、扩展 md_cg/test_evidence_delivery_compact.py；未改 src/MCP工具、排序、正式记忆库或生产配置。研究控制器和数据在独立 E 盘目录。默认关闭；撤销实验 enabled=True 或不加载 G 即回到 D，源代码回滚见单独清单。所有原始轨迹和离线重评分脚本均已保存；673次离线重放零差异，不新增API调用。

**本轮不将 G 升级为默认，不自动提交 PR。** D 的独立价值已有更强证据；G 的保真属性和 DEFER 行为可继续研究，但稳定净收益、真实仓库泛化、私有语料兼容、原生插件G集成都尚未完成。原生G测试profile集成须在人类审核后另行开展。

现在不适合引入预测式 Memory-RSI：已暴露的主要瓶颈仍是可解释的交付损失、字段含义与最终动作不一致，既不需要大型世界模型，也没有证据表明简单规则已经无法选择合适策略。下一阶段优先单独验证可追溯的证据片段/条件表达或最终参数校验，并使用真实仓库/公开任务；不要同时引入多个模块。
