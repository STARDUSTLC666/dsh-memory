# dsh-memory 第五轮完整实验与失败归因报告

本轮确认了特定实验适配器的证据交付损失，并把它与检索、条件过滤和 Agent 实现错误分开。所有结论属于阶段性实验探索；不代表生产插件已改善，不批准上线。

有效主实验为修复后版本 r5-v1.3-feedback：开发 36、验证 72、留出重跑 144，共 252 次 B 阶段 DSH 会话，复用 24 次 A 会话。留出每组 24 次，12 个不同接口、六个家族、每题两次重复。唯一预选候选为 D。

## 1. 先处理实验质量

第四轮 160 次原分数仍为 A=30/40，B=C=D=27/40。三道已知规格不足题单列，不事后重算；vendor tag 返回契约另记为主要由初始代码隐含。第四轮没有设计 A 独有事实必需任务，不能仅从总分证明 Memory 造成全部失败。

第五轮早期版本存在两个需要公开的实验问题：四个非私有事实家族跨拆分重复了行为模板；新目录漏改 project_check 的评分器文件名。前者由新增 12 个不同 B 接口和案例补充验证；后者在 216 次开发/验证/部分留出运行中导致模型没有回合内检查反馈。原始后验行为分数、选择记录和原始轨迹均保留，作为受损诊断，不混入有效主成绩。

修复只改工具入口，并在检查工具错误时停止批次。各组评分、真值、提示、预算、Memory 算法、A 图和反思状态不变。逐组实际注册工具预检以及真实 DSH 回执均验证检查反馈可用。修复后的开发和验证隔离并行，留出在重新选择并封存候选后开始。

部分相同留出任务在故障版本中已被查看过，本轮称为“工具修复后的统一留出重跑”，不冒充未曾暴露过的新封存集。没有依据这些故障结果改算法或答案。新接口只覆盖已见六个家族，不是未见家族或真实仓库 Benchmark。

## 2. 第四轮逐项失败归因

完整审计见 [P0/P1 报告](第五轮_P0_P1审计与归因.md)、[边界补充](第五轮_P0补充_题面与生产边界.md) 和 round4-failure-attribution-reviewed.json。11 次 A 成功/Memory 失败，涉及 8 个任务-重复配对；其中 3 次来自已知规格不足题。多标签计数 D=9、H=8、G=6、A=1、C=1，不应相加当作任务数。

D 多为正确拒绝不适用条件；H 为任务可独立解；G 是声明接口或搜索消耗预算的可见开销，未证明注意力损害；A 是 URL 家族合格来源不足；C 是陈旧事件目标排名 8/9、未进 top-4。没有充分证据把模型返回类型、输入别名、遗漏 import 等失败全部归为错误记忆采用。

B 的正文单项前缀摘录后再截断外层 JSON，40/40 次有外层截断。原始 pack 中出现 ID、正文出现 ID、真正交付关键事实是三个不同指标。该实现属于实验室 raw-experience 适配器，不是正式插件默认配置。

## 3. 数据流与消融边界

A 会话题面事实 → 实际 DSH 修复/行为回执 → 同一 contextual 图中的完整结构化 trace → 固定公开查询 → 原 lexical/RRF top-4 → recall 内层前缀摘录 → 组内条件处理/上下文组装 → 工具 JSON → 可选采用声明与代码编辑 → 回合内外部检查 → 最终独立评分。

|组|唯一变化|
|---|---|
|A|无记忆|
|B|原始实验适配器|
|C|仅严格过滤|
|D|仅来源/条件交付|
|E|A-only Oracle|
|F|等 Token 无关上下文|

C 只过滤 B 的同一候选；D 只从同一候选的完整 trace 投影 A source_document 并保留 A 会话、回执哈希、时间、条件和 unverified 状态。D 不改排序、不额外过滤候选、不改反思。E 只用 A 身份索引和 B 公开命名空间选适用 A 来源。F 不含任务事实，在同一固定查询下与虚拟 D 的完整工具 JSON 等长。

本轮 D 是证据交付组，不是第四轮 D 的条件反思组。本轮所有组反思关闭。没有新增 Curator、Reflector、神经网络、预测器、世界模型、权威记忆库或生产更新。Oracle 不是数学上必然最高的生成成绩，代码能力和随机性仍可使其失败。

固定七工具协议只允许一次 recall，没有向 Agent 开放按 ID 补取完整正文的 get 工具；D 复用底层已有 cg.get。故本轮是一次检索交付的诊断，不代表原生插件完整工具面下的最佳基线。正式插件中 Agent 是否会自行补取、D 是否仍有净收益，尚未验证。

D 对 B 总 Token 变化 12.8%，未缓存输入+输出变化 16.3%。F 对 A 未缓存输入+输出变化 33.0%。缓存、额外正文、调用次数和代码自纠正共同影响总成本，不能把总 Token 差全部解释为算法计算收益。

Oracle 与 D 同为 24/24，未缓存输入+输出较 D 低 24.6%。它只交付适用 A 来源，提示无关候选的上下文开销仍值得独立研究；本轮未把 Oracle 当作可部署算法，也未把过滤与交付组合后重新测分。D 相对 B 多完成 6 次，但多用 12837 个未缓存输入/输出 Token，这是成功与成本的实际取舍。

DSH 的 inputTokens 已是不含缓存读取的输入；未缓存成本代理为 inputTokens+outputTokens，总量另含 cacheReadTokens/cacheWriteTokens。计时包括 DSH 和回合内工具过程，不是纯 API 网络延迟；Memory 工具计时还含 Python 启动，核心检索时间另存 JSON。实际货币账单不可取得，不估算或拿账户余额代替逐次成本。

全轮实际启动 543 次 DSH 会话，其中 541 次有完成记录；A 来源仅实际跑 24 次，不因复制索引重复计算。有效主实验与受损/废止版本开销分别保存在 actual-model-run-accounting.json；中断请求最后一笔未回报用量可能缺失，观察总量是下界。

## 8. 唯一候选与研究结论

验证后重新选择 D：A-document delivery with provenance。候选选择与 SHA256 回执在修复后留出开始前封存，留出不得重新挑赢家。完整要求与候选通过/未通过原因见 candidate-decision.json。

可确认：长期项目事实已经写入、目标经验也被检索到，仍可能因结构化长日志的前缀交付而丢失帮助。对这类任务，恢复原始 A 文档、来源、时间和条件比仅过滤已截断正文更直接。完整证据后的嵌套复制、时间并列和代码实现错误属于另一条瓶颈，不能据模型自述自动归因于 Memory。

不可确认：本轮未证明经验迁移类相对于无记忆有持续净收益，未证明上下文长度本身造成稳定注意力损害，也未证明应启用反思。F 的成绩和逐案例差异只说明当前固定长度控制下的观察；六个家族不足以得出普遍结论。

暂不进入预测驱动 Memory-RSI。现在没有证明不同反思触发策略需按任务选择，也没有证明轻量预测器会胜过简单规则。下一项值得独立检验的是同样的来源保留交付在真实插件/MCP 与真实仓库任务中是否成立；先保持唯一机制和独立验收，不同时加入过滤+交付+反思。ACE/RSI-Anything 的候选比较、外部反馈、独立验证、通过保留与失败回滚可作为研究参考，本轮不训练 JEPA 或自动演化。

## 9. 工程变化、测试和回滚

Memory 产品源码与本轮冻结的 76a1b7ba 基线一致，未新增生产算法变更。唯一候选是实验适配器的上下文组装臂，可通过选择 B 禁用；工具文件名修复只在新实验版本中。新增的是审计、任务规格、真值隔离、工具预检、统计分析和原始数据归档。

隔离源码回归：310 项 PASS，另有 3 项因私有 DB/语料不可用而 SKIP，二者分列。新评分边界 10 项通过；12 个留出参考实现通过、12 个初始实现不通过；三套目录各六组真实注册工具入口预检通过。修复后 252 次运行的实际检查工具错误为 0，每次都观察到有效检查反馈。

另在新目录离线重放一题的六组两次最终实现，共 12 条评分，全与原始结果一致。没有调用 API、读取 Memory DB 或覆盖原成绩；完整 144 条可由同一脚本加 --all 自行复核。

现有草稿 PR 另修正两处变异测试读取编码关键字，不改变实验冻结源码或算法；阶段预发布的历史快照不改。所有生产 DSH 插件和正式记忆库保持未操作。没有自动批准上线或新建未审核 PR。
