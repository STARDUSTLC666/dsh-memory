## 证据损失的完整路径

1. 过去会话被保存为 contextual 图节点，正文是完整 trace JSON，包含 candidate_note、context、events、observations、source_document 等。原始来源正文仍在图中，未被 D 改写。
2. `md_cg/mdcos.py::MdCGOS.recall` 使用 RRF 的候选顺序，在预算不足时用 `excerpt_tokens` 截取正文前缀，标记 `truncated=True`。历史核心对应约 2050–2084 行。这是核心的显式摘录行为，不是唯一损失点。
3. 第五轮实验桥 `comparison-v4-feedback/holdout/memory_bridge.py` 把已经截短的正文放入 normalized items，又把整个 JSON 截到估算 750 token。原始的单条正文、后续条目的元数据或 JSON 尾部均可能继续丢失。第二次截断没有生成模型可用的完整性状态。
4. trace 的排序键使 candidate_note / context / events / observations 先于 source_document。长诊断轨迹占据前缀时，关键事实在第一层摘录中尚未出现。外层再截断可能留下 ID、丢掉事实：看到 ID 不代表收到有效证据。
5. D 对**相同 raw pack ID、相同顺序**调用 `get`，解析 source_document，重新组装来源与条件，再调用 `evidence_delivery.deliver`。第五轮收益来自取回图中已有来源，而非补写答案或改变检索排序。
6. D 仍通过 160 字符步长 / 240 字符窗口的 `query_excerpt` 摘取内容；单个窗口可能切断事实和限定条件。元数据过大或剩余 room < 8 时条目会直接跳过。内部有 source SHA、spans、truncated 记录，但第五轮交给 Agent 的 value 没有携带“必要证据不完整→DEFER”的明确状态。

## D 仍存在的保真缺口

- compact metadata 字段不包含 `non_applicable_conditions` 和 `verification_basis`；这些若只存在于 frontmatter，不能靠 D 保证交付。
- 桥接时用 trace.context 替换原生 condition_space。这保留了实验的确切上下文，却没有证明原生条件全部保留。不能把 D 称为所有条件的完整保真实现。
- `mdcg.py::add` 会补写 condition_space.time_window；源码注释明示这是“观测时间”窗口，缺省以写入时间为锚。它不同于 effective_from/effective_until 或显式 validity 过滤。原生观测窗、来源事件日期和知识有效期必须分别表达。
- 第五轮 B/D 关闭 judge、固定 lexical 路、没有 memory_get 恢复工具。这是受控实验路径，不能代表用户可主动继续检索时的最优原生插件表现。
- 第五轮用 MdCGOS 和合成数据，没有经过 MdCGSecure；其模型结果本身不足以证明身份权限正确。

## 本轮冻结与权限边界

本轮 B/D 的 recall 预算、k、lexical 路、原始两次前缀 / D 来源投影及估算预算保持不变。统一在其外层复用既有 MdCGSecure；所有组使用相同、由受信任实验控制器绑定的 Principal。跨租户使用物理独立图根，private/secret 遵守原生会话归属和 clearance。身份认证仍由原生 MCP 测试单独验证；直接构造 Principal 的试验不是令牌认证测试。
