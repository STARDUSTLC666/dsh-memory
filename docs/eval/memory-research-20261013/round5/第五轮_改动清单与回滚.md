## 审计和复现

- `audit_round4.py`、`report_p0_p1.py`：第四轮逐次数据流与 11 个配对负结果审计。
- `audit_check_feedback.py`：从真实工具回执检查反馈可用性，区分工具错误和任务失败。
- `analyze_stage_quality.py`：完整 A 文档、内层摘录、外层正文、来源、条件、采用声明及代码事实的分阶段见证。
- `analyze_negative_transfer.py`：外部输出是否与错误套用旧规则相符；不据模型自述推定因果。
- `analyze.py`、`select_candidate.py`、预提交回执：配对胜负、家族描述统计、费用代理、不可覆盖的候选选择。
- `preflight_registered_tools.mjs`：调用实际 SDK 注册工具的 execute 入口，检查失败/成功反馈及拒绝边界。
- `audit_actual_runs.py`：全轮调用与消耗，包含受损数据，不重复计算复用 A 会话。
- `verify_preservation.py`：历史压缩包、原有改动、冻结算法/数据哈希检查。
- `offline_reproduce.py`：不访问 API/Memory DB，在新目录重放行为分数。
- `export_evidence.py`：导出原始数据、冻结公开源码和报告，凭据扫描、排除私钥及运行时、ZIP 完整性检查。

所有真值读取的分析脚本都位于生成/检索/评分调用链之外，不参与 Oracle 构造。新机制只存在于显式实验臂，生产默认状态仍关闭。
