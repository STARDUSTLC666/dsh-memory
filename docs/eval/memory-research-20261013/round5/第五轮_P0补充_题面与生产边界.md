# P0 补充：题面与生产边界

原第四轮成绩和首份 P0/P1 归因文件不改动。以下补充仅收紧解释范围。

`dependency-version-2` 的公开题面只说按 priority 选 vendor artifact，没有显式说返回 tag 字符串。初始 `choose_artifact` 代码的返回表达式确实为 `...['tag']`，因此它可以从现有接口行为推断，但不像完整的公开类型契约那样明确。原先三道已确认规格不足题仍单独保留；本题另记为“返回契约主要由初始代码隐含”。整个 record 与 tag 的错误不能单独作为 Memory 导致负迁移的证据。

第四轮 B 和第五轮 B 都指特定实验室 raw-experience 适配器：lexical 单路 RRF、固定 top-4、`include_work=True`、`judge=False`、嵌套轨迹前缀摘录后再次截断工具 JSON。它们不是正式 DSH 插件的默认配置。本轮发现的交付损失首先适用于这一实验数据格式和适配器，不能直接推广成“生产 dsh-memory 一般降低成功率”。

本次固定七工具、一次 recall 的诊断协议没有向 Agent 开放按 ID 补取完整正文的 Memory get 工具。底层现有 `cg.get` 能读完整记录，D 正是复用了它。因此本轮测的是“一次检索的交付面是否丢失证据”，不是原生插件完整工具面下的最佳行为。正式插件允许完整读取时，Agent 可能通过补取自行恢复事实；这一生产基线尚未在本轮模型对照中验证，必须作为下一阶段独立检查，不能把 D 的实验收益直接折算为正式插件升级收益。

第四轮的 11 个 A 成功/Memory 失败样本中，适用条件拒绝经常是正确行为；未检索到、接口预算消耗、输入所有权错误、缺少 import、题面约定不完整均需分别处理。现有证据不足以把 30/40 与 27/40 的全部差异归因于错误经验被采用，也不足以证明注意力干扰。

第五轮的新实验使用真实 DSH CLI 与实验工具，再调用同一 Memory Python 核心；这证明该隔离实验调用链，不等于本轮已经通过生产插件原生 MCP、生产数据或可见 UI 验收。第三轮原生 MCP、身份回归证据应单独引用，不能与本轮调用链混算。
