# 发布阻塞与后续建议

结论：建议开始正式代码审查；当前不满足生产发布验收。

1. 三项历史私有语料测试及主干新增一项同源测试缺少合法提供的原始数据；公开替代不能判定原语料等价性。需要有权限的数据提供方执行验收或由人类作明确风险裁决。
2. D1 对 INCOMPLETE 只提供明确状态，模型有一次仍提交 ANSWER；另一次保留过期原文后仍使用旧事实。调用端的拒答状态执行尚无工程保证，不可将状态标签当作可靠约束。
3. 24 个新任务来自 3 个标准领域、共用八类场景，并非真实仓库问题集；不具备证明广泛生产收益或无严重退化的样本量。
4. macOS、原私有库规模、生产 profile、真实敏感正文与用户可视化界面均未验。现有测试证明限定权限矩阵和元数据哨兵安全，不是对任意秘密内容的形式化证明。
5. API 实付费用不可得；端到端耗时为单机两分片实测，不能视作并发服务 SLA。
6. 全仓手写行号文档门禁在统一构建的干净上游和候选均有相同 142 条红锚；本候选新增 0，未篡改基线/allowlist，仍未全绿，发布前需独立处理或由维护者裁决。
7. D1 白名单不复制全部原生 consistency 诊断；相同事实、不同诊断呈现的收益尚无单因素因果证明，被省略警告是否影响信任决策需独立审查。

先保持 evidence_preserving 默认关闭，进入人工代码审查并验证调用端行为，再扩充独立真实任务与授权语料。无需预测控制器、JEPA、大型世界模型或自动自我修改。此次静态交付策略优化不称为递归自我改进。
